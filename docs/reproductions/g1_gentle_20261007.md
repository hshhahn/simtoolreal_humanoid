## Start a new training run

Run setup, CPU jobs, and simulation on Slurm compute nodes. Follow
[SLURM_SETUP.md](../../SLURM_SETUP.md) to install the pinned environment.

From the repository root, dispatch to an allocated four-GPU node with a fresh
output directory:

```bash
srun --jobid=YOUR_JOB_ID --overlap --exact --nodes=1 --ntasks=1 \
  --cpus-per-task=32 --gpus-per-task=4 --gpu-bind=none \
  env RUN_DIR=/shared/path/to/new_original_run \
  bash slurm/run_g1_gentle.sh original
```

For randomized heights, replace `original` with `height145` and use another
fresh output directory. The wrapper supplies the recorded settings and accepts
additional training arguments/Hydra overrides. With no checkpoint argument,
the task-policy training starts from scratch.

## Replay a checkpoint

For portable replay, copy the archived `dependencies/sonic_v1_1/` directory
into the installed checkout at `models/GEAR-SONIC/sonic_v1_1/`. This retains
the exact frozen model used by these policies.

Run the following inside a GPU Slurm compute shell from the installed checkout
root. Set `G1_ARCHIVE` to the archive's current location:

```bash
G1_REPO="$PWD"
G1_ARCHIVE=/shared/path/to/g1_gentle_best_20261007
G1_SNAPSHOT=original_heights_epoch_3870
G1_TASK=Isaacsimenvs-G1-Wuji-Sonic-v0
mkdir -p "$G1_REPO/visualizations/g1_preserved/$G1_SNAPSHOT"
source ./activate_simtoolreal.sh
python isaacsimenvs/play_video.py \
  --checkpoint "$G1_ARCHIVE/$G1_SNAPSHOT/checkpoint.pth" \
  --saved_config "$G1_ARCHIVE/$G1_SNAPSHOT/training/rank_0/.hydra/config.yaml" \
  --task "$G1_TASK" --agent rl_games_sapg_cfg_entry_point \
  --num_envs 96 --steps 1500 --video_fps 25 --width 640 --height 640 \
  --seed 42 --deterministic --sapg_coefficient 0 --all_tools_grid \
  --checkpoint_tolerance 0.039858076721429825 \
  --camera_eye 1.6 -2.1 1.7 --camera_target 0 0.25 0.8 \
  --out "$G1_REPO/visualizations/g1_preserved/$G1_SNAPSHOT/rollout.mp4"
```

For the height checkpoint, use
`G1_SNAPSHOT=randomized_heights_epoch_5583` and
`G1_TASK=Isaacsimenvs-G1-Wuji-Sonic-Height-v0`. The command writes six
`rollout_<tool>.mp4` clips plus camera/starting-pose metadata. Each clip is
30 seconds at 1× speed: 1,500 control steps at 50 Hz, captured every two steps
and encoded at 25 FPS. The archive includes the combined reference videos
and the rendering/composition helpers used to produce them.

Saved configs restore smoothing and height ranges. Bundled table paths are
rebased to the current checkout for portable replay. The explicit tolerance
restores the checkpoint-time curriculum value: 0.0398580767, or an effective
keypoint threshold of about 0.0597871 m after the 1.5 keypoint scale.
Omitting it would replay with the looser initial task tolerance.

## Fine-tune from an archived policy

Use the matching preset and a fresh output directory. The `weights` mode
loads actor/critic weights and normalization while starting fresh optimizers,
rollouts and iteration counters:

```bash
srun --jobid=YOUR_JOB_ID --overlap --exact --nodes=1 --ntasks=1 \
  --cpus-per-task=32 --gpus-per-task=4 --gpu-bind=none \
  env RUN_DIR=/shared/path/to/new_finetune_run \
  bash slurm/run_g1_gentle.sh original \
  --checkpoint /shared/path/to/g1_gentle_best_20261007/original_heights_epoch_3870/checkpoint.pth \
  --checkpoint_load_mode weights \
  env.termination.success_tolerance=0.039858076721429825
```

For the height policy, select `height145` and
`randomized_heights_epoch_5583/checkpoint.pth`. The explicit tolerance
retains the recorded task difficulty.

The trainer also accepts `--checkpoint_load_mode resume`, but this is partial
training-state restoration. The checkpoint retains the actor optimizer and
training counters; it does not retain the critic optimizer, physics/SONIC
history, smoothing state, curriculum state, or RNG state. Restored observation
and recurrent buffers can therefore disagree with a newly reset simulator.
The archive supports policy reuse and fine-tuning; it does not provide an
exact uninterrupted simulation continuation.
